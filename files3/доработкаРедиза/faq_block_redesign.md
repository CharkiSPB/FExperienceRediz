# FExperience — переработка блока «Часто задаваемые вопросы»

## Цель

Переработать уже существующий блок «Часто задаваемые вопросы» в общей визуальной системе нового редизайна FExperience.

Это **не создание нового FAQ с нуля**.

Основная задача — изменить композицию существующего блока так, чтобы он воспринимался как editorial-информационный блок в стиле всего нового сайта: с большим количеством воздуха, тонкой графикой, аккуратными разделителями и минималистичным accordion.

Ключевой визуальный принцип:

> **Слева — графический editorial-якорь: иконка розы ветров + заголовок. Справа — accordion из 5 вопросов.**

Композиция должна быть спокойной, дорогой и функциональной одновременно.

---

## 1. Общая композиция

Блок разделён на две вертикальные части:

```text
┌────────────────────────────────────────────────────────────────────┐
│                                                                    │
│  [РОЗА ВЕТРОВ]          │  01  Вопрос                              │
│                         │  ──────────────────────────────────────  │
│  ЧАСТО ЗАДАВАЕМЫЕ       │  02  Вопрос                              │
│  ВОПРОСЫ                │  ──────────────────────────────────────  │
│                         │  03  Вопрос                              │
│                         │  ──────────────────────────────────────  │
│                         │  04  Вопрос                              │
│                         │  ──────────────────────────────────────  │
│                         │  05  Вопрос                              │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

### Левая часть

Содержит:

- иконку розы ветров;
- заголовок «Часто задаваемые вопросы».

### Правая часть

Содержит:

- accordion;
- 5 вопросов;
- горизонтальные разделители между вопросами;
- интерактивное состояние раскрытия ответа.

### Между частями

Обязательно должна присутствовать:

> **тонкая вертикальная линия-разделитель**

Она проходит между левой и правой колонками и визуально связывает весь блок.

---

## 2. Левая часть — иконка розы ветров

Использовать существующую иконку розы ветров, если она уже есть в проекте.

Не создавать новую сложную иллюстрацию без необходимости.

Иконка должна восприниматься как:

- editorial graphic;
- тонкая линейная графика;
- навигационный / экспедиционный символ;
- визуальный якорь блока.

Она не должна выглядеть как:

- большая иконка из UI-kit;
- жирная пиктограмма;
- цветная туристическая иллюстрация;
- декоративный элемент с сильным визуальным шумом.

### Цвет

Использовать спокойный цвет, соответствующий текущей палитре сайта.

Предпочтительно:

- тёмный графит;
- приглушённый коричнево-графитовый;
- при необходимости очень небольшой терракотовый акцент.

Не делать всю иконку ярко-оранжевой.

---

## 3. Заголовок

Основной заголовок:

> **Часто задаваемые вопросы**

Заголовок должен находиться в левой колонке рядом с / под иконкой в соответствии с существующей типографической системой.

Не превращать его в огромный hero-заголовок.

Иерархия должна быть editorial:

```text
[иконка]

Часто задаваемые
вопросы
```

или эквивалентная композиция, если существующий компонент уже задаёт другую вертикальную структуру.

Важно сохранить:

- текущую шрифтовую систему проекта;
- характерную editorial-типографику;
- нормальный межстрочный интервал;
- ощущение воздуха.

---

## 4. Вертикальный разделитель

Между левой и правой частью должна быть тонкая вертикальная линия.

Принцип:

```text
ЛЕВАЯ ЧАСТЬ       │       ПРАВАЯ ЧАСТЬ
                   │
                   │
                   │
                   │
```

Линия должна быть:

- очень тонкой;
- визуально вторичной;
- спокойной;
- не выглядеть как граница карточки.

Предпочтительно использовать тот же принцип линий, который уже используется в других editorial-блоках сайта.

Не использовать толстый border.

### Важный нюанс

Вертикальный разделитель должен восприниматься как **структурный editorial-разделитель**, а не как рамка вокруг контента.

---

## 5. Правая часть — FAQ accordion

Правая часть содержит **5 вопросов**.

Использовать существующие вопросы и ответы из текущей реализации.

Не придумывать новый FAQ-контент без необходимости.

Не переписывать существующие ответы только ради нового дизайна.

Структура:

```text
01  Вопрос
────────────────────────────────────

02  Вопрос
────────────────────────────────────

03  Вопрос
────────────────────────────────────

04  Вопрос
────────────────────────────────────

05  Вопрос
```

---

## 6. Горизонтальные разделители

Каждый вопрос отделён от следующего тонкой горизонтальной линией.

Это обязательная часть визуального решения.

Линии должны:

- быть тонкими;
- использовать спокойный цвет;
- проходить по ширине правой части;
- не быть слишком контрастными;
- создавать ощущение editorial layout.

Не использовать тяжёлые рамки вокруг каждой FAQ-карточки.

То есть не:

```text
┌──────────────┐
│   Вопрос     │
└──────────────┘
```

А:

```text
Вопрос
──────────────────────────────

Вопрос
──────────────────────────────
```

---

## 7. Номера вопросов

Если существующая структура позволяет, использовать нумерацию:

```text
01
02
03
04
05
```

Номера должны быть небольшими и визуально вторичными.

Они могут использовать терракотовый акцент, но это не обязательно.

Главное:

> номера должны помогать сканировать список, а не превращаться в декоративный шум.

Если существующий FAQ-компонент уже имеет собственную нумерацию, сохранить её и адаптировать визуально.

---

## 8. Состояние закрытого вопроса

В закрытом состоянии строка вопроса должна быть максимально чистой.

Пример:

```text
01    Как проходит бизнес-экспедиция?                         +
──────────────────────────────────────────────────────────────
```

Справа можно использовать:

- существующую иконку раскрытия;
- плюс;
- стрелку;

в зависимости от того, что уже используется в проекте.

Не создавать новый набор UI-иконок без необходимости.

---

## 9. Состояние открытого вопроса

При клике вопрос раскрывается:

```text
01    Как проходит бизнес-экспедиция?                         −

      Ответ на вопрос расположен здесь.
      Текст читается спокойно и не перегружает композицию.

──────────────────────────────────────────────────────────────

02    Следующий вопрос                                        +
```

Ответ должен:

- появляться плавно;
- иметь комфортную ширину строки;
- сохранять хорошую читаемость;
- не менять всю геометрию блока резко;
- использовать существующую типографическую систему.

Не использовать агрессивные анимации.

---

## 10. Accordion behavior

Сохранить существующую логику accordion, если она уже реализована.

Если текущая логика допускает только один открытый вопрос:

> сохранить такой режим.

Если текущая логика допускает несколько открытых вопросов:

> не менять функциональность без необходимости.

Главный приоритет:

> **изменяем визуальную композицию, а не бизнес-логику FAQ.**

---

## 11. Motion

Анимация должна быть минимальной.

Рекомендуемый характер:

- плавное раскрытие высоты;
- лёгкое изменение opacity ответа;
- небольшое вращение / изменение состояния иконки;
- transition примерно 250–400ms.

Не использовать:

- spring-анимации;
- сильный scale;
- bounce;
- glow;
- резкое появление текста.

FAQ должен ощущаться как часть дорогого editorial-интерфейса.

---

## 12. Цветовая система

Использовать существующую палитру нового редизайна:

Основной светлый фон:

```css
#FFF1E5
```

Дополнительный светлый слой:

```css
#F2DFCE
```

Акцент:

```text
терракотовый / тёплый оранжевый
```

Основной текст:

```text
тёмный графит / почти чёрный
```

Линии:

```text
приглушённый нейтральный оттенок
```

Не использовать ярко-белые карточки поверх светлого фона без необходимости.

Не делать FAQ оранжевым блоком.

---

## 13. Background и texture

FAQ должен визуально продолжать общий светлый editorial-фон сайта.

Если на странице уже используется лёгкая бумажная / grain texture:

> сохранить её.

Не добавлять отдельную тяжёлую текстуру специально для FAQ.

Общий фон должен ощущаться как дорогая бумага / editorial print, а не как обычный flat UI.

---

## 14. Ширина и spacing

На desktop блок должен использовать ширину страницы рационально.

Ориентировочно:

```text
левая часть: 30–35%
правая часть: 65–70%
```

Это ориентир, а не жёсткое значение.

Главное:

- левая колонка не должна быть слишком узкой;
- правая часть должна иметь достаточно ширины для длинных вопросов;
- вертикальный разделитель должен быть хорошо заметен, но не доминировать;
- между краями блока и содержимым должен сохраняться editorial whitespace.

Не делать слишком широкие пустые поля внутри правой части.

---

## 15. Высота блока

Высота должна определяться содержимым.

Не задавать искусственную большую высоту только ради заполнения экрана.

Если все 5 вопросов закрыты:

> блок должен оставаться компактным и аккуратным.

При раскрытии ответа:

> высота блока увеличивается естественно.

Не оставлять огромную пустую область под accordion.

---

## 16. Desktop layout

Рекомендуемая структура:

```text
┌──────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  [ROSE]               │  01  Вопрос                              +  │
│                       │  ─────────────────────────────────────────  │
│  ЧАСТО ЗАДАВАЕМЫЕ     │  02  Вопрос                              +  │
│  ВОПРОСЫ              │  ─────────────────────────────────────────  │
│                       │  03  Вопрос                              +  │
│                       │  ─────────────────────────────────────────  │
│                       │  04  Вопрос                              +  │
│                       │  ─────────────────────────────────────────  │
│                       │  05  Вопрос                              +  │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

Левая и правая части должны быть визуально сбалансированы.

---

## 17. Mobile layout

На мобильном вертикальный разделитель между колонками не должен сохраняться как вертикальная линия.

Композиция перестраивается:

```text
┌────────────────────────────────┐
│                                │
│  [РОЗА ВЕТРОВ]                 │
│                                │
│  ЧАСТО ЗАДАВАЕМЫЕ              │
│  ВОПРОСЫ                        │
│                                │
├────────────────────────────────┤
│                                │
│  01  Вопрос                    +│
│  ───────────────────────────── │
│                                │
│  02  Вопрос                    +│
│  ───────────────────────────── │
│                                │
│  03  Вопрос                    +│
│  ───────────────────────────── │
│                                │
│  04  Вопрос                    +│
│  ───────────────────────────── │
│                                │
│  05  Вопрос                    +│
│                                │
└────────────────────────────────┘
```

На mobile:

- левая часть становится верхней;
- accordion идёт ниже;
- вертикальный divider превращается в горизонтальный разделитель между секциями или полностью убирается, если spacing уже достаточно;
- вопросы остаются полноширинными;
- touch target должен быть комфортным.

---

## 18. Адаптивность

Не допускать:

- горизонтального overflow;
- слишком длинных строк;
- обрезания вопросов;
- наложения номера и текста;
- слишком маленькой области клика;
- разрушения вертикального разделителя на tablet.

На промежуточных размерах допустимо постепенно уменьшать ширину левой колонки.

---

## 19. Архитектурный принцип

Использовать существующий FAQ-компонент и существующие данные.

Логика:

```text
EXISTING FAQ DATA
        ↓
EXISTING FAQ COMPONENT
        ↓
новая editorial-композиция
        ↓
левая колонка + divider + accordion
```

Не создавать отдельную параллельную data/model систему.

Не дублировать вопросы и ответы в новом компоненте.

Не создавать отдельную страницу только ради нового FAQ.

---

## 20. Что сохранить

Обязательно сохранить:

- существующие вопросы;
- существующие ответы;
- существующую data/model architecture;
- существующую accordion-логику;
- существующие accessibility-механизмы;
- keyboard interaction;
- focus states;
- semantic markup;
- текущие ссылки внутри ответов;
- существующую систему шрифтов;
- общую систему spacing, если она уже используется проектом.

Если существующий компонент уже соответствует части требований — не переписывать его без необходимости.

---

## 21. Что изменить

Изменить прежде всего:

- композицию блока;
- разделение на две части;
- левую editorial-зону;
- размещение розы ветров;
- размещение заголовка;
- вертикальный divider;
- визуальный стиль горизонтальных разделителей;
- визуальный стиль строк accordion;
- spacing;
- desktop/mobile layout.

---

## 22. Что НЕ делать

Не делать:

- пять отдельных карточек;
- пять glass-card;
- отдельные рамки вокруг каждого вопроса;
- яркий оранжевый фон;
- большие цветные UI-иконки;
- тяжёлые тени;
- стандартный Bootstrap-like accordion;
- огромные плюсики;
- толстые borders;
- декоративные элементы ради заполнения пустоты;
- новую data/model architecture;
- дублирование FAQ-контента;
- отдельную тёмную карточку вокруг accordion;
- вертикальный divider на mobile;
- огромную фиксированную высоту блока;
- чрезмерные animation effects.

---

## 23. Визуальная связь с остальным редизайном

FAQ должен ощущаться частью той же системы, что и:

- блок цифр;
- блок регионов;
- блок экспедиции;
- editorial-фотографии;
- печати;
- карты;
- другие информационные секции.

Общие принципы:

> тонкие линии  
> спокойная типографика  
> бумажный фон  
> editorial whitespace  
> небольшие графические якоря  
> терракотовые акценты  
> отсутствие визуального шума

FAQ не должен выглядеть как отдельный UI-компонент из другого сайта.

- [ ] Каждый вопрос отделён тонкой горизонтальной линией.

- [ ] Ответы используют существующие данные.
- [ ] Сохраняется существующая логика открытия/закрытия.
- [ ] Состояние open/close визуально понятно.
- [ ] Есть комфортная зона клика.
- [ ] Анимации плавные и минимальные.

- [ ] Используется общая editorial-эстетика FExperience.
- [ ] Фон соответствует общей цветовой системе.
- [ ] Терракотовый используется только как акцент.
- [ ] Линии тонкие и спокойные.
- [ ] Роза ветров выглядит как editorial graphic.
- [ ] Нет тяжёлых UI-карточек.

### Architecture

- [ ] Используется существующий FAQ-компонент, если он есть.

- [ ] Не создана параллельная data/model architecture.
- [ ] Не затронуты другие секции страницы.
- [ ] Существующая функциональность FAQ не сломана.
- [ ] Accessibility сохранена.

## Итоговая концепция

Было:

```text
Обычный FAQ / accordion
01 Вопрос
02 Вопрос
03 Вопрос
04 Вопрос
05 Вопрос
```

Стало:

```text
┌──────────────────────────┬─────────────────────────────────────────┐
│                          │                                         │
│      [РОЗА ВЕТРОВ]       │  01  Вопрос                         +  │
│                          │  ─────────────────────────────────────  │
│  ЧАСТО ЗАДАВАЕМЫЕ        │  02  Вопрос                         +  │
│  ВОПРОСЫ                 │  ─────────────────────────────────────  │
│                          │  03  Вопрос                         +  │
│                          │  ─────────────────────────────────────  │
│                          │  04  Вопрос                         +  │
│                          │  ─────────────────────────────────────  │
│                          │  05  Вопрос                         +  │
│                          │                                         │
└──────────────────────────┴─────────────────────────────────────────┘
```

**Смысл блока:**

> **Визуальный символ экспедиции → информационный вопрос → быстрый доступ к ответу.**

Главный визуальный приём — **две editorial-колонки, разделённые одной тонкой вертикальной линией**, где слева находится роза ветров и заголовок, а справа — чистый accordion из пяти вопросов с горизонтальными разделителями.
