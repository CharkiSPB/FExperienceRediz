# FExperience — переработка блока с картами континентов

## Задача

Переработать блок с картами регионов/континентов на главной странице по визуальному принципу выбранного референса.

Цель — уйти от ощущения **четырёх больших пустых карточек с картами** и создать более плотную editorial-композицию, где континенты сами заполняют пространство, а цифры, названия и точки создают визуальный ритм.

**Референс использовать как принцип композиции, а не копировать буквально.**

---

## 1. Общая концепция

Блок должен восприниматься не как:

> «4 карточки с картами континентов»

а как:

> **единое editorial-картографическое поле для выбора направления экспедиции.**

Сохранить существующие регионы, данные, ссылки и навигацию.

Меняется прежде всего визуальная подача.

---

## 2. Цветовая система

Уйти от ярко-оранжевого цвета континентов к **приглушённой терракотовой гамме**.

Основной цвет:

```css
--region-terracotta: #B86F57;
```

Допустимые близкие оттенки:

```css
#A9624D
#B8735A
#C08068
```

Использовать разные уровни прозрачности:

```css
rgba(184, 111, 87, 0.12)
rgba(184, 111, 87, 0.25)
rgba(184, 111, 87, 0.45)
rgba(184, 111, 87, 0.75)
```

### Континенты

Континенты должны быть:

- мягко-терракотовыми;
- editorial;
- слегка полупрозрачными;
- с тонким контуром.

Например:

```css
fill: rgba(184, 111, 87, 0.12);
stroke: rgba(184, 111, 87, 0.55);
```

При hover:

```css
fill: rgba(184, 111, 87, 0.20);
stroke: rgba(184, 111, 87, 0.80);
```

**Не использовать яркий orange для больших площадей.**

---

## 3. Фон

Использовать новую систему:

```css
--paper-main: #FFF1E5;
--paper-secondary: #F2DFCE;
```

Не делать каждую карточку отдельной насыщенной плашкой.

Допустима почти незаметная вариация:

```css
background:
  linear-gradient(
    135deg,
    rgba(255, 241, 229, 0.7),
    rgba(242, 223, 206, 0.45)
  );
```

Градиент должен восприниматься как изменение плотности бумаги, а не как цветная карточка.

---

## 4. Карточки регионов

Если текущая архитектура использует сетку 2×2, сохранить её.

Но уменьшить визуальный вес карточек.

Проблема текущей версии:

> большие карточки → большая пустая площадь → карта выглядит второстепенным элементом.

Новая версия:

> карта + цифра + название + количество экспедиций формируют один плотный editorial-модуль.

Не использовать тяжёлые borders и card shadows.

---

## 5. Структура карточки

Сохранить реальные названия и данные проекта.

Рекомендуемая структура:

```text
01

АФРИКА
3 экспедиции

                    [контур карты]
                    [точки]
```

Или:

```text
01                       •
АФРИКА
3 экспедиции

                  [ CONTINENT ]
```

Главное:

**название + число + карта** должны работать как единый визуальный модуль.

---

## 6. Карты

Карты должны занимать заметную часть композиции, но не превращаться в огромные иллюстрации.

Допустимо:

- слегка смещать карту вправо;
- слегка смещать карту вниз;
- позволять ей немного выходить за внутреннюю сетку;
- использовать асимметричное размещение.

Не центрировать карту математически.

Карта должна заполнять пустоту и одновременно оставаться лёгкой.

---

## 7. Номера

Добавить/сохранить небольшие номера:

```text
01
02
03
04
```

Номер должен:

- быть небольшим;
- создавать editorial rhythm;
- не конкурировать с названием;
- использовать основной тёмный цвет или приглушённую терракоту.

Не делать номера огромными.

---

## 8. Названия регионов

Названия — один из главных визуальных элементов.

Использовать существующую editorial-типографику проекта.

Они должны хорошо читаться ещё до рассмотрения карты.

Не делать названия слишком маленькими.

---

## 9. Количество экспедиций

Сохранить существующие реальные значения.

Формат:

```text
АФРИКА
3 экспедиции
```

Количество должно быть вторичным относительно названия, но достаточно заметным.

Не превращать число экспедиций в отдельную dashboard-метрику.

---

## 10. Точки на карте

Активные направления обозначать небольшими терракотовыми точками.

Цвет:

```css
#B86F57
```

Можно добавить очень мягкий halo:

```css
box-shadow:
  0 0 0 4px rgba(184, 111, 87, 0.10);
```

Не использовать neon.

Не делать яркий orange glow.

Точка должна выглядеть как картографическая отметка.

---

## 11. Hover

Hover должен слегка оживлять карту.

При наведении:

1. карта становится немного насыщеннее;
2. точки становятся чуть заметнее;
3. карта может слегка увеличиваться;
4. стрелка/индикатор перехода становится заметнее.

Например:

```css
transition:
  opacity 300ms ease,
  transform 500ms cubic-bezier(.2,.7,.2,1),
  fill 300ms ease,
  stroke 300ms ease;
```

Не использовать резкие трансформации.

---

## 12. Границы

Не использовать стандартные жёсткие borders:

```css
border: 1px solid #ddd;
```

Предпочтительно:

- практически невидимая граница;
- мягкий градиент;
- разделение пространством;
- различие плотности бумажной поверхности.

Карточки должны ощущаться частью одной композиции, а не четырьмя отдельными UI-компонентами.

---

## 13. Desktop

Сохранить 2×2, если это соответствует существующей архитектуре:

```text
┌──────────────────────────┐  ┌──────────────────────────┐
│ 01                       │  │ 02                       │
│ АФРИКА                   │  │ АЗИЯ                     │
│ 3 экспедиции             │  │ 5 экспедиций             │
│                  [MAP]   │  │                  [MAP]   │
└──────────────────────────┘  └──────────────────────────┘

┌──────────────────────────┐  ┌──────────────────────────┐
│ 03                       │  │ 04                       │
│ ...                      │  │ ...                      │
│ ...                      │  │ ...                      │
│                  [MAP]   │  │                  [MAP]   │
└──────────────────────────┘  └──────────────────────────┘
```

Но визуально эти четыре области должны ощущаться как **единое картографическое поле**.

---

## 14. Связь между картами

Допустимы очень тонкие визуальные связи:

- точки;
- небольшие маркеры;
- общая сетка;
- единая терракотовая графика.

Не проводить очевидные маршрутные линии через всю страницу.

Чистота композиции важнее декоративности.

---

## 15. Анимация

При появлении блока можно использовать лёгкий stagger:

1. появляется текст;
2. появляются контуры карт;
3. появляются точки.

Например:

```css
opacity: 0 → 1;
transform: translateY(8px) → translateY(0);
```

Stagger примерно 80–120ms.

Анимация должна быть практически незаметной.

---

## 16. Mobile

На мобильном перейти в одну колонку, но **не делать четыре огромных вертикальных карточки**.

Пример:

```text
┌──────────────────────────────┐
│ 01                       •   │
│ АФРИКА                       │
│ 3 экспедиции                 │
│                     [ MAP ]  │
└──────────────────────────────┘
```

Карта занимает правую часть, текст — левую.

Высота карточки умеренная.

---

## 17. Что НЕ делать

Не использовать:

- ярко-оранжевые континенты;
- насыщенный orange background;
- отдельный цвет для каждого континента;
- большие серые карты;
- огромные пустые карточки;
- glassmorphism;
- тяжёлые shadows;
- толстые borders;
- neon glow;
- чрезмерную анимацию;
- огромные цифры;
- стандартный dashboard UI.

Не превращать региональный блок в набор разноцветных карточек.

---

## 18. Связь с остальным редизайном

Блок должен продолжать визуальный язык уже реализованного Hero и статистики.

### Hero

- editorial typography;
- стекло;
- мягкие терракотовые/оранжевые акценты;
- фирменная печать;
- много воздуха.

### Статистика

- три горизонтальных модуля;
- линейные иконки;
- мягкие разделители;
- editorial rhythm.

### Региональный блок

- картографическая графика;
- терракотовый цвет;
- бумажные поверхности;
- минимальные UI-границы;
- editorial navigation.

Все блоки должны ощущаться частью одной дизайн-системы.

---

## 19. Acceptance checklist

- [ ] Четыре региона сохранены.
- [ ] Существующие данные и ссылки не изменены.
- [ ] Карточки визуально компактнее.
- [ ] Убрано ощущение четырёх огромных пустых cards.
- [ ] Карты занимают более значимую часть композиции.
- [ ] Континенты переведены из ярко-оранжевого в приглушённую терракоту.
- [ ] Основной цвет карт около `#B86F57`.
- [ ] Используются разные уровни opacity.
- [ ] Точки используют ту же терракотовую систему.
- [ ] Нет neon/glow.
- [ ] Границы карточек мягкие или практически невидимые.
- [ ] Названия регионов хорошо читаются.
- [ ] Номера `01–04` создают editorial rhythm.
- [ ] Hover мягко оживляет карту.
- [ ] Используются `#FFF1E5` и `#F2DFCE`.
- [ ] Mobile остаётся компактным.
- [ ] Блок визуально связан с Hero и статистикой.

---

## Итоговая идея

Нужно перейти от:

> **«четыре большие карточки с картами континентов»**

к:

> **«единое editorial-картографическое поле, через которое пользователь выбирает направление экспедиции».**

Главные инструменты:

**континенты + терракотовая картография + цифры + точки + воздух + мягкие бумажные поверхности.**

Терракотовый цвет должен быть **приглушённым и дорогим**, а не просто заменять старый orange на другой яркий цвет.
