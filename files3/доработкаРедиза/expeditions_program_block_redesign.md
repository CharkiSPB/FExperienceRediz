# FExperience — переработка блока «Экспедиции» в блок программы ближайшей экспедиции

## Цель

Переработать уже существующий блок «Экспедиции», сохранив текущие визуальные компоненты и общий стиль сайта.

Это **не создание нового блока с нуля**. Основная задача — изменить композицию и заменить правую часть с превью следующих экспедиций на **три визуальных preview дня программы текущей главной экспедиции**.

Итоговая логика:

> **Слева — ближайшая экспедиция в существующей glass-card. Справа — региональный контекст + три визуальных preview дня программы этой же экспедиции.**

---

## 1. Общая композиция

Блок должен занимать **100% ширины viewport**.

На desktop:

```text
┌──────────────────────────────────────┬────────────────────────────────────────────┐
│                                      │                                            │
│     EXISTING GLASS CARD              │  АФРИКА                                   │
│                                      │                                            │
│     БЛИЖАЙШАЯ ЭКСПЕДИЦИЯ              │  существующий текст о регионе              │
│                                      │  / экспедиции                              │
│     весь существующий контент         │                                            │
│                                      │  ┌─────────┐ ┌─────────┐ ┌─────────┐      │
│     [существующая кнопка]             │  │ IMAGE   │ │ IMAGE   │ │ IMAGE   │      │
│                                      │  │ ДЕНЬ 01 │ │ ДЕНЬ 02 │ │ ДЕНЬ 03 │      │
│                                      │  │ краткое │ │ краткое │ │ краткое │      │
│                                      │  │ описание│ │ описание│ │ описание│      │
│                                      │  └─────────┘ └─────────┘ └─────────┘      │
│                                      │                                            │
└──────────────────────────────────────┴────────────────────────────────────────────┘
```

Левая часть — доминирующая.

Правая часть — более компактная, но визуально заполненная.

---

## 2. Левая часть — существующая glass-card

Существующий glass-card сохранить практически без изменений.

Сохранить:

- glass-эффект;
- форму;
- прозрачность;
- текущую типографику;
- заголовок;
- дату;
- описание;
- CTA-кнопку;
- внутреннюю композицию;
- существующие hover/transition состояния.

Изменяется прежде всего **расположение карточки**: она становится левой частью нового full-width блока.

Не создавать новую glass-card, если существующий компонент уже доступен.

---

## 3. Динамическая главная экспедиция

Главная карточка не должна быть постоянно привязана к ЮАР.

Использовать существующие данные экспедиций и дату.

Алгоритм:

```text
текущая дата
      ↓
будущие экспедиции
      ↓
сортировка по дате
      ↓
ближайшая экспедиция
      ↓
glass-card
```

Не хардкодить ЮАР или Вьетнам как постоянную главную экспедицию.

---

## 4. Правая часть — единая тёмная editorial-зона

Правая половина должна иметь единый глубокий тёмный фон.

Это **не отдельная карточка** вокруг текста.

Вся правая область является одной поверхностью:

```text
┌────────────────────────────────────────┐
│ АФРИКА                                 │
│                                        │
│ существующий текст                     │
│                                        │
│ [ preview ] [ preview ] [ preview ]    │
└────────────────────────────────────────┘
```

Использовать глубокий тёплый графит / коричнево-графитовый оттенок.

Не использовать чистый `#000`.

Тёмная зона должна сочетаться с:

```css
#FFF1E5
#F2DFCE
```

и терракотовыми акцентами.

---

## 5. Существующий текст справа

Существующий текстовый блок сохранить и переместить в правую часть.

Не переписывать содержание без необходимости.

Сохранить:

- существующий заголовок;
- labels;
- основной текст;
- типографику;
- иерархию;
- существующие декоративные элементы.

Его задача:

> дать короткий контекст о регионе и подготовить пользователя к просмотру программы.

Текст должен занимать верхнюю часть правой зоны и оставлять место для трёх preview.

---

## 6. Вместо следующих экспедиций — программа

Это ключевое изменение.

Убрать предыдущую логику:

```text
главная экспедиция
+
preview Вьетнам
+
preview следующая экспедиция
```

Сделать:

```text
главная экспедиция
+
preview ДЕНЬ 01
+
preview ДЕНЬ 02
+
preview ДЕНЬ 03
```

Все три карточки относятся **к одной текущей главной экспедиции**.

---

## 7. Визуальный принцип карточек программы

Карточки должны быть выполнены **по принципу референса**:

- большая фотография;
- информация о дне поверх изображения или в нижней части;
- короткое описание непосредственно на карточке;
- три карточки в одну горизонтальную линию на desktop.

Принцип:

```text
┌──────────────────┐
│                  │
│      IMAGE       │
│                  │
│                  │
│  ДЕНЬ 01         │
│  Кейптаун        │
│  короткое        │
│  описание        │
└──────────────────┘
```

**Изображение — главный визуальный элемент.**

Не превращать preview в три текстовые колонки.

---

## 8. Содержимое карточки дня

Каждая карточка содержит:

### Обязательно

- номер дня;
- название / локацию / ключевую активность;
- короткое описание;
- изображение.

### Опционально

- дату;
- небольшой label;
- стрелку / ссылку на полную программу, если такая навигация уже существует.

Текст должен быть коротким.

Preview — это тизер дня, а не полное описание программы.

---

## 9. Три preview должны заполнять правую часть

Карточки должны быть достаточно крупными, чтобы визуально заполнять правую область, но не конкурировать с большой glass-card.

Ориентир:

```text
левая часть: 55–60%
правая часть: 40–45%
```

В правой части:

```text
текст
────────────
[ preview ] [ preview ] [ preview ]
```

Не оставлять большое пустое пространство между текстом и preview.

---

## 10. Динамическая программа

Программа должна автоматически соответствовать текущей главной экспедиции.

Алгоритм:

```text
найти ближайшую будущую экспедицию
        ↓
получить её программу
        ↓
взять первые 3 дня
        ↓
сформировать preview
```

При смене ближайшей экспедиции автоматически меняются:

- название;
- изображение;
- дата;
- описание;
- регион;
- контекстный текст;
- изображения дней;
- названия дней;
- описания дней.

Весь блок работает как единая динамическая система.

---

## 11. Если дней меньше трёх

Не создавать фиктивные дни.

Если есть 2 дня:

```text
[ ДЕНЬ 01 ] [ ДЕНЬ 02 ]
```

Если есть 3 и более:

```text
[ ДЕНЬ 01 ] [ ДЕНЬ 02 ] [ ДЕНЬ 03 ]
```

Если дней больше трёх — использовать первые три как preview.

При наличии существующего перехода на полную программу можно показать:

```text
Смотреть всю программу →
```

Не создавать новую навигационную систему без необходимости.

---

## 12. Full-width

Внешний блок:

```css
width: 100%;
```

Не ограничивать всю композицию стандартным `max-width`, если это создаёт поля по краям.

Внутри можно использовать существующую систему padding.

Визуально блок должен идти от края до края экрана.

---

## 13. Цветовая система

Основной светлый фон:

```css
#FFF1E5
```

Светлый акцентный слой:

```css
#F2DFCE
```

Правая часть:

```text
глубокий тёплый графит
```

Акцент:

```text
терракотовый / тёплый оранжевый
```

Использовать акцент экономно:

- labels;
- номера дней;
- ссылки;
- небольшие графические детали.

Не делать preview полностью оранжевыми.

---

## 14. Hover и motion

Preview могут иметь лёгкий hover:

- мягкий zoom изображения;
- небольшое изменение opacity;
- лёгкое движение стрелки;
- плавный transition 250–400ms.

Не использовать сильное свечение, агрессивный параллакс или резкие анимации.

---

```text

существующий текст

┌──────────────────────┐
│        IMAGE         │
│                      │
│  ДЕНЬ 01             │
│  короткое описание   │
└──────────────────────┘

┌──────────────────────┐
│        IMAGE         │
│                      │
│  ДЕНЬ 02             │
│  короткое описание   │
└──────────────────────┘

┌──────────────────────┐
│        IMAGE         │

```

Тёмный фон объединяет текст и все preview.

Главная glass-card остаётся первым элементом.

---

## 16. Архитектурный принцип

Использовать существующие компоненты:

```text
EXISTING MAIN EXPEDITION CARD
              ↓
        левая колонка
```

```text
EXISTING TEXT BLOCK
              ↓
        правая колонка
              ↓
     PROGRAM PREVIEWS
```

Не создавать новую параллельную систему данных.

---

## 17. Что НЕ делать

Не делать:

- новый блок с нуля;
- новую data/model logic;
- постоянную привязку к ЮАР;
- постоянную привязку к Вьетнаму;
- preview следующих экспедиций;
- четыре одинаковые большие карточки;
- повторение блока регионов;
- новую glass-card вместо существующей;
- переписывание существующего текста;
- три текстовые колонки без изображений;
- отдельный тёмный фон вокруг каждой preview;
- большие пустые пространства.

---

## 18. Acceptance checklist

- [ ] Блок full-width.
- [ ] Существующая glass-card сохранена визуально.
- [ ] Glass-card находится слева.
- [ ] Главная экспедиция определяется ближайшей будущей датой.
- [ ] ЮАР не захардкожен.
- [ ] Правая часть имеет единый тёмный фон.
- [ ] Существующий текст перемещён вправо.
- [ ] Текст сохранён без ненужного переписывания.
- [ ] Вместо следующих экспедиций используются preview дней программы.
- [ ] Все preview относятся к текущей главной экспедиции.
- [ ] Каждая preview содержит изображение.
- [ ] Каждая preview содержит номер дня.
- [ ] Каждая preview содержит короткое описание.
- [ ] На desktop три preview расположены горизонтально.
- [ ] На mobile preview корректно перестраиваются вертикально.
- [ ] Программа берётся из существующих данных.
- [ ] При смене главной экспедиции программа автоматически меняется.
- [ ] Не создаются фиктивные дни.
- [ ] Не создаётся новая параллельная data/model logic.
- [ ] Следующие экспедиции больше не используются как preview.
- [ ] Блок не дублирует блок регионов.
- [ ] Блок воспринимается как презентация ближайшей экспедиции и её программы.

## Итоговая концепция

Было:

```text
┌──────────────────────┬──────────────────────────────┐
│                      │ существующий текст           │
│  GLASS: ЮАР          │                              │
│                      │ [ Вьетнам ] [ другая ]       │
└──────────────────────┴──────────────────────────────┘
```

Стало:

```text
┌──────────────────────┬─────────────────────────────────────┐
│                      │ АФРИКА                              │
│  GLASS: ближайшая    │                                     │
│  экспедиция          │ существующий текст                   │
│                      │                                     │
│  [контент]           │ [ДЕНЬ 01] [ДЕНЬ 02] [ДЕНЬ 03]       │
│  [кнопка]            │ [ image ]  [ image ]  [ image ]    │
│                      │ [кратко]   [кратко]   [кратко]      │
└──────────────────────┴─────────────────────────────────────┘
```

**Смысл блока:**

> **Куда едем → что это за регион → как выглядит программа.**

Главная экспедиция определяется динамически по ближайшей дате, а три preview всегда показывают первые три дня её программы.
